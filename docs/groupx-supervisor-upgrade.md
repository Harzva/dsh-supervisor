# GroupX 与 Supervisor 可靠性升级

本机候选版本：GroupX 0.1.0-alpha.29，Supervisor 0.2.7。

UI 延续现有会话入口：主要操作保持可见，策略与上限、模型与角色等设置可展开；会诊结果及成员意见支持完整换行。控件提供键盘焦点，GroupX 讨论深度支持方向键选择，排队和运行中的会诊均可取消。颜色优先使用宿主主题变量，窄屏按单列排列。此版本保留此前可靠性升级的 Host 协议与授权边界。

Supervisor 通过可选 Host 服务 `groupxCouncil`（protocolVersion 1）请求建议，不再导入 GroupX 内部运行模块。两者继续复用已安装的中立角色库，不建立第二份角色定义。

## 进展与续行

- 原生 Goal 存在时，active、paused、blocked、complete 均拥有续行权；读取失败也暂停旧 Supervisor 续行。检查覆盖 watchdog、计划缺失提示、固定提示、自动建议与人工采纳，并在耐久发送声明后再次核对。
- 原生 `todo/write` 与 Supervisor 托管计划分开保存。观察优先使用原生清单；相同任务中完成项增加为推进、减少为退步、未变化为停滞。工具成功不单独证明推进。取消、任务变化及证据不足显示未知。
- 同一持久事件序号不重复计轮。只保存工具输出 hash，不保存工具原文到进展记录。

## 有界会诊

每个用户任务最多两次会诊、累计预留 12 次模型调用，默认每次预留 6 次（2 名成员的提案、修订与汇总，含一次失败余量）、60 秒；单次硬上限 8 次。第二次只可使用剩余预算。预算在调用前原子持久化；失败、取消、超时及重启不返还已预留额度。实际消耗在 GroupX 回执中单独报告；未能确认时使用保守上限。

自动会诊须由用户为当前任务显式开启。相同停滞信号连续三轮后可触发，两次会诊至少间隔两轮；原生 Goal 暂停、阻塞、完成或状态未知时不自动会诊。新用户任务、关闭监督和重启撤销自动授权。手动会诊始终只形成建议，不直接执行主会话。成员由 GroupX 服务端既有选中模型冻结，至少需要两个有效成员。

GroupX requestId 支持并发与持久重试去重；相同 ID 改变载荷拒绝。重启遗留的 running 回执变为 interrupted，不重放模型调用。取消与卸载中止等待，过期结果不成为 Supervisor 建议。公开回执只包含有界摘要、成员意见、显式阻塞异议和产物 hash，排除内部记录、提示正文和本机存储路径。

## 操作

现有 Supervisor 输入面板提供进展状态、原生 Goal 状态、会诊预算、发起/取消按钮及自动会诊复选框。命令同等支持：

```text
/supervise council
/supervise council cancel
/supervise council-auto on
/supervise council-auto off
```

安装候选包前保留原版本制品和配置快照。候选应在独立 DSH_HOME 下通过完整测试、打包校验、真实 Cordis 服务装载及客户端渲染检查；生产配置不用于试验。学习、训练学院、模型微调和跨运行时适配不在此版本范围。
