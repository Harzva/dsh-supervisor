# 会话矩阵导师系统需求分析

## 目标

把会话矩阵升级为稳定的多导师监督台：后台状态刷新时卡片不改变尺寸和位置；导师拥有明确角色、责任范围、稳定配色，可负责多个会话并发起协作、Handoff 与新会话接管。

## 做与不做

做：

- 固定卡片布局、显式详情抽屉、快照排序。
- 多导师注册表、主责/协作分配与持久化。
- 同导师稳定色彩、固定 SVG 槽位和无布局动画。
- 基于 `compaction/summary` 的上下文健康度。
- 可审计、可重试、幂等的 Handoff 状态机。
- 通过宿主权威服务创建真实会话并继承工作区、Preset 与导师关系。

不做：

- 不复制或公开原始聊天日志。
- 不在浏览器伪造会话实体。
- 不自动删除或归档源会话。
- 不因便利放宽权限、沙箱或凭据边界。

## 核心场景

1. 会话运行、思考或生成建议时，卡片高度和位置保持稳定。
2. 用户可识别每张卡片的主责导师、角色、职责和协作导师。
3. 同一导师负责的卡片使用同一颜色，状态颜色与导师颜色分离。
4. 导师可查看自己负责的全部会话、发送协作备注并转交责任。
5. 成功压缩两次时预警，三次时建议 Handoff。
6. 导师请求旧会话编写结构化 Handoff，经确认后创建新会话并投递交接内容。
7. 创建或投递失败后可重试且不产生重复会话。

## 非功能需求

- 轮询状态变化导致的卡片高度差不超过 1px。
- 排序仅在用户显式操作或成员增删时改变。
- 业务状态在宿主重启后恢复。
- Host 与 Client 只传递有界 JSON。
- 所有可选能力局部失败、可卸载、可回滚。
- 支持键盘操作和 `prefers-reduced-motion`。

## 验收边界

- 自动化测试覆盖导师归一化、分配稳定性、持久化、压缩计数、Handoff 幂等和错误恢复。
- 真实 Web Profile 验证卡片、滚动、排序、按钮、抽屉、导师动画和交接闭环。
- 禁用新增路由或插件行后，DSH 仍能启动并保留源会话。
