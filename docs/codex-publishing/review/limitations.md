# Review-relevant limits

- This is a local desktop plugin. The complete version requires Node 22+, an installed and authenticated Codex CLI, locally available models, and host permission for the selected project's protected `.codex/supervisor` directory and the CLI's own cache. Codex 0.149.0 on macOS is the verified contract; other versions and operating systems are not claimed verified.
- The panel does not discover the active project automatically. The user selects a real existing project; installation-cache cwd is not treated as that project. Bindings use host thread context and server-issued IDs. Projects cannot be switched through an arbitrary path on subsequent status or write calls.
- The current supported host interfaces do not expose the current conversation's actual model/effort through a reliable read-only query. Execution settings are separately selected from the native catalog. CLI defaults are not described as inherited chat settings.
- Supervision and review skills use the invoking host's model and delegation capabilities. Faculty/mentor IDs are responsibility profiles, not independent users, grants or native actors. DSH routes remain migration metadata.
- Enabling the gate grants no new task authority. Off blocks new dispatch and retries while running work can finish; Stop additionally requests cancellation. Cancelling or uncertain is not confirmed termination. There is no guarantee of instant cancellation, native exactly-once dispatch, formal consensus, or an enforced monetary/token budget.
- Each execution uses its own helper-created thread and immutable grant. Ambiguous acceptance or process loss requires receipt reconciliation. The plugin does not dispatch into arbitrary existing chats, create native Goals, install hooks/watchdogs, schedule future wakeups or continuously scan user conversations.
- Local records include bounded proposal instructions, domain prompts, grants, receipts, model settings, checks and handoffs. Plugin evidence omits raw transcripts and stderr; the native Codex host still maintains its own normal thread/cache records and sends authorized work to the configured native service. No claim is made that native inference stays entirely on-device.
- No publisher-operated authentication, cloud MCP service, telemetry collector, payment processor or commerce workflow is included. Account availability, approvals, quotas and any native inference charges remain those of the user's Codex service. A blocked cache/path or model must be reported, not silently bypassed by global permission changes.
- UI rendering and bridge interactions have been checked in an isolated AppBridge host. Installed native tool metadata/resources were checked separately. An automated actual click in the native Codex desktop window was not observed; a clean reviewer walkthrough remains required.
