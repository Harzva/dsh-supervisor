# Internal policy source audit

**Internal evidence — do not deploy as public website content.**

Reviewed: 2026-10-18. Behavior baseline: plugin 0.4.0 with Codex CLI 0.149.0. The 0.4.1 release updates publishing materials without changing execution behavior; it is not a new behavior-validation claim. Source baseline before this documentation change: `f2d59bc2fafd3a19226eedd2ab6bb784ccf2dcf4`. This is a focused source review, not a penetration test, provider-policy audit, legal compliance certification or official directory approval.

## Local data and runtime findings

| Policy statement | Implementation evidence |
| --- | --- |
| The package uses local stdio MCP, not a Harzva remote server. | `plugins/codex-supervisor/mcp.json` starts `node ${PLUGIN_ROOT}/runtime/mcp-server.mjs` and passes `${PLUGIN_DATA}`. `server/panel-server.mjs` connects `StdioServerTransport`; no publisher HTTP endpoint is configured. |
| Panel association is explicit and project/conversation bound. | `server/bindings.mjs` uses host `_meta.threadId` UUID, validates an absolute real directory and generates random binding IDs. `bindings.v1.json` stores `id`, `ownerThreadId`, `workspace`, `label`. Maximum 100 bindings and 512 KiB. Opening/listing does not create project state. |
| Panel tool results include potentially personal local paths. | `server/panel-server.mjs` returns public binding workspace/label plus bounded control, mentor count, job IDs/status/attempt counts, requested/confirmed model and effort. These travel through the MCP host/UI bridge; private prompts and raw transcripts are not returned. App-only tool visibility is not a general confidentiality guarantee about host processing. |
| Bundled UI has no independent browser persistence or remote-resource requirement. | Owned `ui/panel.js` uses `App.callServerTool`; no cookies, localStorage, sessionStorage, fetch or telemetry calls were found in that entry point. UI resource CSP has empty `connectDomains`, `resourceDomains`, `frameDomains`; HTML and bridge dependencies are bundled. This finding does not describe desktop-host behavior. |
| Native CLI owns login, provider access and its records. | `scripts/native-executor.mjs` uses `spawn` to run installed `codex app-server`. Owned code contains no authentication-file reads, direct model API client or provider credential store. It inherits process environment and can map existing macOS static HTTP(S) proxies to the child; no global HOME/CODEX_HOME or network changes. The CLI may receive environment-based provider credentials; do not claim no component ever processes credentials. |
| Plugin execution can cause model-service transfers. | `scripts/execution.mjs:promptFor` sends the proposed instruction, acceptance criteria, declared verification and correlation markers to an owned worker. `native-executor.mjs` uses thread/start or owned thread/resume plus thread/queue/add. Native agents may include accessible project content using their configured provider. The plugin cannot promise offline inference or provider non-retention. |
| Worker-tool network is requested disabled, separate from model connection. | `native-executor.mjs:DEFAULT_ARGS`, `checkPermissions`, execute and verifyCommand request workspace-write, bounded writable roots, on-request human approval and networkAccess false; validation rejects a weakened response. `command/exec` lacks a turn approval stage, so verification argv must already be authorized. |
| Project state may contain sensitive text. | `scripts/supervisor.mjs` stores config including domainPrompt/legacy route; task assignments, timestamps and checkpoints. `execution-store.mjs` stores original proposal instruction, success criteria, verification argv/file specs, digest, grant, native IDs, attempt metadata and verification results. `control.mjs` and `settings.mjs` store workspace, revisions, timestamps, switch/model settings. |
| Private state is local and bounded, not encrypted or auto-expiring. | `state.mjs` uses `.codex/supervisor/`, mode 0700 for new directories and 0600 for new files, symlink rejection, exclusive locks and atomic replacement. State bounded to 1 MiB. Settings/control are bounded to 4 KiB. Existing permission mode and platform behavior require deployment verification. There is no encryption-at-rest implementation or timed deletion. |
| Raw logs/transcripts are processed transiently but not stored in plugin state. | Native adapter counts/discards stderr; bounded stdout JSON RPC events and thread receipts are processed in memory for correlation. Verification reads file bytes and command stdout/stderr in memory, persisting only structured metadata/hashes/byte counts/status. Execution metadata validator disallows raw transcript/log fields. Proposal instructions and user summaries are stored; they must not be mislabeled as non-personal metadata. |
| Checkpoint count is not a deletion timeline. | `supervisor.mjs` keeps the latest 20 checkpoints per task and up to 100 tasks. `state.mjs:ensureHandoff` writes digest-addressed Markdown, never deleting old handoffs. Execution store keeps up to 100 jobs. Binding registry has no unbind/TTL. Size limits may require manual maintenance; neither closing nor uninstalling erases the project state. |
| Input filtering is limited. | `supervisor.mjs:safeCheckpointText` and execution string validation reject common credential patterns/private-key markers/raw role-style transcripts. These heuristics cannot certify arbitrary files, summary text, argv or native context free of sensitive data. Public policy prohibits restricted data rather than promising complete prevention. |
| Stop is a cancellation request and does not roll back effects. | Panel stop closes project control gate, calls cancel for authorized/active/failed/uncertain/needs-action jobs. Live execution polls stored cancellation, interrupts exact owned turn/verification process and requires matching terminal receipts. Unconfirmed outcomes remain uncertain. Completed jobs and unauthorized proposals are preserved. No rollback implementation. |
| No arbitrary-chat takeover or independent continuation service. | Execution workflow targets owned worker threads and rejects receipt ownership conflicts. Skills preserve user scope, bounded reviews and native permissions. No watchdog, automatic future wakeup or forced cost/token budget is implemented. |

- Successful deployment and public HTTP responses. The prepared effective date is 2026-10-18; the intended URLs are `https://harzva.github.io/supervisor/`, `/supervisor/support/`, `/supervisor/privacy/`, `/supervisor/terms/`.
- The publishing organization's identity-verification status, local-MCP partner eligibility/allowlist, submission acceptance or approval.
- Provider retention, residency, training controls, host histories/caches or behavior of all installed native integrations. Users' account/settings and applicable provider terms determine these.
- Cross-platform behavior, all future CLI versions or cancellation of user actions outside owned Supervisor jobs.

The four public documents now contain no unresolved tokens. Deploy only those allowlisted Markdown sources after the release owner's final check. The private source repository need not be made public to host policy pages, and nothing in this task authorizes publishing private source contents.

## Official requirements checked

[Plugin guidelines](https://developers.openai.com/plugins/plugin-guidelines), checked 2026-10-18, require a published privacy policy covering data categories, purposes, recipient categories, retention and controls; minimize data, avoid restricted inputs and misleading endorsement claims. They require transparent scope and meaningful user control.

[Submission requirements](https://developers.openai.com/plugins/deploy/submission), checked 2026-10-18, require website, support, privacy and terms HTTPS links for MCP review, belonging to the same publisher. Homepage/author metadata does not replace those listing fields. Final submission also has separate icon, review-case and video requirements owned by the release workflow.

These sources inform the document shape. They do not establish that this implementation or publisher will be accepted.

[GitHub Pages data collection](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection) and [GitHub General Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement), checked 2026-10-18, document that GitHub Pages records visitor IP addresses for security and that GitHub controls its own service data handling. The policy does not promise zero access logs or a hosting deletion period under Harzva's control.
