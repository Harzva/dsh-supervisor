# 会话矩阵导师系统验收报告

日期：2026-08-26

## 结论

本轮升级已通过本地自动化、真实 Digital-Me Web 页面和服务重启后的持久化复测。会话矩阵卡片保持固定几何；Supervisor 角色、责任范围、颜色、逐角色模型、协作分配和 Handoff 状态由 Host 权威数据驱动；Handoff 能创建唯一目标会话、保留源会话并继承工作区与 Preset。

## 自动化结果

- `dsh-supervisor npm run check`：11 项测试通过。
- `zhitro-brandos-session-board npm run check`：语法和包检查通过。
- 两个插件均通过 `preflight-dsh-extension.mjs`。
- `digital-me` Profile 组合检查通过：150 个 loader rows，无重复，两个目标 row 均存在。

## 真实页面结果

- 矩阵加载 42 张既有卡片；完成两次 Handoff 后为 44 张。
- 可见卡片统一为 `252px`；前 18 张卡片无 overflow。
- 连续两个 12 秒轮询窗口：顺序、位置和尺寸最大变化均为 `0`。
- 标签与快捷输入合并为单行底栏；空标签显示紧凑 `+ 标签`，不再单独占据整行或制造底部空洞。
- 模式按钮命中测试通过：点击中心的顶层 DOM 为按钮本身；`提意见` 和 `关闭` 均成功切换。
- 同 Supervisor 颜色稳定：架构 `#2563eb`、执行 `#7c3aed`、研究 `#0f766e`；卡片 SVG 固定 `40×40`。
- 架构/研究/执行/验证/交接分别使用指南针、取景镜、闪电、盾牌、桥接 SVG；当前 Profile 的 3 个角色图形签名互不相同。
- 点击角色卡只切换模型配置上下文，不误改主责；“设为主责”和“+ 协作”是独立操作。
- DSH 模型目录成功载入 30+ 个候选；选单和手填 `provider/model` 都可用。
- 实测代码 Supervisor 与研究 Supervisor 保存不同模型后互不覆盖；服务重启后两项都恢复，随后已清除测试覆盖并恢复继承。

## Handoff 闭环

- 冷会话请求通过官方 Connection API 唤醒，不再依赖“活动 agent”。
- 当前运行时按 `assistant/chunk` 聚合草稿，并在 `turn/end` 捕获；模型失败会进入 `failed_retryable`，不再永久停留在 drafting。
- Provider 返回 `Insufficient Balance` 时，页面准确显示原因，并可选择不含原始日志与绝对路径的安全摘要。
- 真实创建目标会话时，源会话保留、目标只出现一次，持久日志中 Handoff `user/message` 只有一条。
- 冷源会话的工作区与 Agent Preset 已由矩阵已知事实补齐；目标卡片实测显示与源卡一致的工作区短名与 Preset。
- 服务重启后，完成状态、固定目标 id、源/目标卡片和导师分配均恢复。
- 完成后的源卡可“打开目标会话”，目标卡可“打开源会话”。

## 已知外部条件

- 测试期间模型供应端曾返回 `Insufficient Balance`；这不是本地状态机错误。安全摘要降级路径已覆盖该情况。
- 验收期间主动重启服务后、连接尚在重试时，矩阵首次挂载曾触发一次 ErrorBoundary；等待连接稳定并整页重载后未再复现，44 张卡完整恢复。控制台同时记录了预期的 connection retry 警告。

## 恢复方式

从 Digital-Me Profile 的 loader 中移除或禁用 `dsh-supervisor` 与 `zhitro-brandos-session-board` row，再重启 Web 服务即可停用新功能。该操作不会删除源会话、目标会话或原始会话日志；持久导师状态保留在独立 store 中，便于重新启用后恢复。
