# 01-需求分析：Supervisor 圆桌意见/共识记录 + 图结构

> 生成：接管模式意见记录增强
> 关联：`dsh-supervisor/src/index.js`、`src/supervisor-store.js`
> 前提：本功能独立于 role-registry 中立化 Phase；是对 supervisor 接管链路的记录增强。
> 状态：需求（未进入编码）

## 1. 项目目标

接管/提意见模式下，监督角色（学院）各自发表的意见、以及主席裁决出的共识意见，**结构化落盘并按轮次留存**，形成可回溯的历史，便于用户查阅"谁说了什么、共识是什么、谁与谁分歧"，并支持 graph 可视化。

## 2. 做与不做

### 做
- supervisor-store 增加**圆桌历史**持久化：每轮圆桌落盘 `{ roundId, sessionId, at, opinions[], consensus, verdict, 裁决依据 }`。
- `suggestFor` 在产出意见+共识后，**结构化落盘**（而非仅进程内 state）。
- 裁决依据（judge 输入）改为**结构化**（`[{facultyId, name, text}]`），与意见一致落盘。

### 不做
- 不改 GroupX / 不进入 role-registry Phase。
- 不动 supervisor 建议逻辑 / 接管注入逻辑。
- 本阶段只做**数据层 + 可喂图**；可视化 UI 留到下阶段。

## 3. 场景

- 用户接管模式下多次圆桌 → 每轮意见+共识都落盘，可翻历史。
- 需要知道"策略学院 vs 代码学院是否有分歧" → 从裁决依据还原。

## 4. 功能需求表

| ID | 需求 | 验收 |
|---|---|---|
| FR-D1 | 每轮圆桌结构化落盘意见们 | store 出现 roundtable 记录，含每位学院 `{facultyId,name,text,ok}` |
| FR-D2 | 落盘共识意见 | 记录含 `consensus` 文本 |
| FR-D3 | 落盘裁决依据（结构化） | 记录含 `opinions[]` 原始输入（judge 所见） |
| FR-D4 | 按轮次留存（非覆盖） | store 含多轮 roundtable 记录 |
| FR-D5 | 落盘分歧/一致标注 | 记录含 `verdict`（'一致' | '分歧' | 空） |
| FR-D6 | 数据可喂 graph | 从记录能还原 学院→共识 边 / 分歧边 |

## 5. 非功能

- 持久化走现有 `mutate`/原子写（仿 appendRelay），不引入新存储。
- 容量上限（仿 MAX_RELAYS=500）。
- 不破坏现有 supervisor 状态结构（FORMAT_VERSION 兼容）。

## 6. 数据层结构（定义）

```jsonc
// supervisor-state.v1.json 新增字段
"roundtables": [
  {
    "roundId": "rt-<uuid>",
    "sessionId": "<sid>",
    "at": 1234567890,
    "opinions": [
      { "facultyId": "strategy", "name": "策略学院", "text": "…", "ok": true }
    ],
    "verdict": "一致" | "分歧" | "",
    "consensus": "主席裁决出的共识文本"
  }
]
```
- `opinions[]` = 裁决依据（judge 输入）的**结构化形式**，图据此还原边。
- `verdict` 由 judge 输出中的「分歧：/一致」解析，供画分歧/一致边。

## 7. 开放问题
- verdict 解析：从 judge 文本正则提取「分歧：」/「一致」——若是「分歧：…」标注，需进一步识别哪些学院相左（下阶段深化）；本阶段先落 `verdict` 字段。
