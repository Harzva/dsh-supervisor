# 02-架构设计（数据层）：Supervisor 圆桌记录

> 关联：`01-需求分析.md`；目标：结构化落盘意见/共识/裁决依据，形成可喂图的历史。

## 1. 分层图

```
suggestFor（宿主，进程内）───┐
  · 收集 participants 意见        │  写入
  · judge 裁决得到 consensus      ▼
  └─> appendRoundtable(record) ──> supervisor-store（耐久）
                                     └─ state.roundtables[]（原子写，容量上限）
                                            │
                                            ▼
                      图可视化（下阶段）<── snapshot() / getRoundtables(sid)
```

## 2. 模块职责

| 模块 | 改动 | 职责 |
|---|---|---|
| `src/supervisor-store.js` | 加 `roundtables[]` + `appendRoundtable(record)` + `getRoundtables(sid)` | 持久化圆桌轮次 |
| `src/index.js` `suggestFor` | 意见/共识产出后构造 record 并 `appendRoundtable` | 结构化落盘（含裁决依据 opinions[]） |
| `src/mentor-registry.js` | 无改动 | （意见已含 facultyId/name/text） |

## 3. 数据流

```
suggestFor:
  participants.map(→ opinion{facultyId,name,text,ok})   // 已有 p.facultySuggestions
  judge(opinions) → consensus + verdictText
  record = { roundId, sessionId, at, opinions, verdict, consensus }
  store.appendRoundtable(record)
```

## 4. store 接口新增

```ts
appendRoundtable(record): Promise<Record>   // mutate('roundtable.append', push + cap)
getRoundtables(sessionId): Promise<Record[]> // snapshot().roundtables filter by sid
```
- 容量上限 `MAX_ROUNDTABLES = 500`（仿 MAX_RELAYS）。
- `FORMAT_VERSION` 保持 1，`normalizeState` 增加 `roundtables: Array.isArray(...)? slice : []`（向后兼容，旧文件无此字段则空数组）。

## 5. verdict 解析

`consensus` 文本由 judge 输出；`verdict` 从文本推断：
- 含「分歧：」前缀 → `'分歧'`
- 含「一致」→ `'一致'`
- 否则 `''`
- 解析函数放 `src/index.js`（`parseRoundtableVerdict(text)`，纯函数，便于单测）。

## 6. 边界与约束

- 仅在 `faculties.length>0`（圆桌模式）落盘；单导师模式不落。
- 失败静默（`appendRoundtable` 失败只记日志，不影响建议注入）。
- 不影响现有 `assignment/health/handoff` 结构。

## 7. 数据可喂图验证（FR-D6）

从 `record` 可还原：
- 节点：`opinions[].facultyId`（各学院）+ `consensus` + `roundId`。
- 边：每个 `opinion → consensus`（送入裁决）；`verdict==='分歧'` 时存在学院间分歧（下阶段细化），`verdict==='一致'` 则无。
