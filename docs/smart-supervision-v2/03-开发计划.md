# DSH Smart Supervision v2 开发计划

> 状态：规划已批准；P0 的源码、P10 锁值、透明 Git 基线和 private 远端已建立，但生产 Profile 锁文件闭环复核发现漂移，P0 保持部分完成。P1/P2 未授权。

## 1. 执行规则

1. 一个阶段使用一个新会话；不跨阶段实现。
2. 一个阶段是一个验收单位。跨仓阶段在每个仓库各形成一个职责单一的 commit，并共享同一份阶段证据。
3. 每阶段先读本计划、架构、需求和相关源码，再修改。
4. 文档与源码冲突时停止实现，先回写规划或建立 ADR，不在代码里暗选方案。
5. 测试跟随功能同阶段提交；不得把关键测试推迟到总验收。
6. 所有真实安装先经过隔离 Profile；不得以生产 Profile 作为开发环境。
7. 任何阶段失败都停在最近通过验收的 commit；不得用未授权模型、固定“继续”提示或放宽权限作为降级。
8. 不删除 v1/v2 Store、源会话、Handoff 或用户 Profile。回滚以禁用 Loader row、恢复 pinned artifact 为主。
9. 发布前执行公共秘密/路径扫描；规划、制品和提交不得包含凭据、`.env`、原始聊天、诊断转储或本机绝对路径。
10. 每个“新会话提示词”前都必须先加载本目录 README、01～04；提示词只限定当阶段，不能跳过验收矩阵。

## 7. P4：Smart Store、Goal policy seam 与监督上下文

### 目标

建立 side-by-side v2 持久状态，并为 stock Goal Driver 增加最小 final policy seam，完成“不抢调度、可取消、只交付目标 Goal turn”的监督闭环。

### 任务

- [ ] 实现 `smart-supervision.v1.json`、原子写、串行 mutation、上限和未知版本 fail-closed。
- [ ] 实现 stable GoalSubject + exact bound GoalRef 的 Policy attach/update/detach CAS 和完整生命周期表；Goal 操作仍走官方 API。
- [ ] Policy attach 在 Host 层强制至少一条用户确认的 successCriterion；模型/规则草案未确认只能保存 draft，不能进入 observing。
- [ ] 在 upstream Goal Round Driver 实现覆盖每个 queue candidate 的 `goal/before-next-round`（completed 可空）、pendingCompletion、45 秒 deadline、allSettled fail-local 与最终重检；零 listener 完全走 stock fast-path，maintenance 冲突 whenIdle 合并重试。
- [ ] 保留 `turn-stopping` 仅作无副作用 provisional watermark；最终 Assessment skeleton 只在同一 correlationKey 的 before-next-round seam 生成一次。
- [ ] 使用 `agent/inbox/claimed` 跟踪 exact GoalMessageSource 与 deliverTo；human/ordinary/subagent turn 永不渲染监督 section。
- [ ] 注册 Host-fiber 单例 `systemPrompt.context('supervisor:assessment')`；provider 同步、total、内部 catch，Profile suppression 有 typed capability gate。
- [ ] 为 SystemPrompt 增加公开只读 runtimeContextCapability(agent)+revision/change seam；unknown/false 默认禁止自动能力，不私探 private layer。
- [ ] 实现 DeliveryRecord pending→bound→admitted/invalidated/superseded；初始/resume candidate 可绑定，crash 依据 exact message/snapshot 日志恢复。
- [ ] 修正尚未 admitted 的 Goal runtime-context snapshot 为 non-restorable，reservation 失效后不得恢复进 human turn。
- [ ] Goal/policy revision、竞争人类输入、resume/dispose/unload 递增 generation/abort 旧任务；重复 Supervisor Service 实例 fail closed。
- [ ] 人类 nextTurn 只 abort Driver preparation controller，pendingCompletion 标记 superseded-consumed；不得调用 agent.cancel/清 inbox，后续 queue 用 completed=undefined。
- [ ] listener 非空时决定 disposition 后 append model-invisible policy-seam checkpoint，并在 reservation/followup 或释放 human wake 前显式 await `ctx.sessions.flush()`；flush 后二次重检，竞争输入需追加并 flush superseded-consumed；flush 故障 fail-local、不 disarm，并从 durable Goal/human message、turn-end、checkpoint 重建 pendingCompletion。crash retry 使用稳定 correlationKey，零 listener 不 append/flush 该事件。
- [ ] 完成 runtime-context superseding/clear/replay/compaction、Goal driver invariant、Round 计数、Stop hook steer 和竞争输入测试。
- [ ] 实现 v1 side-by-side dry-run/apply marker，但本阶段只迁移已确认 RoleRef/policy，不移动 Handoff。

### 验收

- 同一 Goal turn 多次 `turn-stopping` 仍只产生一个最终 seam/Assessment；wrong ref/round、pre-step reject 和 stale Agent 不触发。
- listener throw/timeout 时 Goal 保持可续行且不 disarm；Goal edit/pause/clear、dispose 或竞争输入则 supersede preparation，不创建 reservation。
- 零 listener 与 stock 路径无可观察差异；maintenance acquisition conflict 不 disarm，whenIdle 后最多一次合并重试。
- 用户消息在 preparation 中进入时立即 abort，先于下一 Goal Round 执行；旧结果不出现在 human turn。
- 目标 Goal pre-step 的最新 runtime-context snapshot 中 supervisor section 恰有一个且 digest 正确；其他 context 改变可生成 superseding snapshot，固定 Goal message 不变且 roundsStarted 只增长一次。
- `includeRuntimeContext=false`/suppression 产生 context-unavailable capability，P7 可消费的 auto-admission gate 返回 false；provider/Store 错误不使 pre-step 失败。
- Goal turn 因 steer 产生多个 step 时每步保持同一冻结 section；匹配 turn/end 后 tracker 清除，下一 human turn 为零。
- pending/bound/admitted 的三处 crash window均可确定恢复；resume 后第一轮即使 completed 为空也能绑定 pending Artifact。
- checkpoint append 但未 flush 的 crash 会用同一 correlation 幂等重放；flush 后 crash 不重复；flush 期间 human 竞争最终持久为 superseded-consumed，Goal reservation 为 0。
- phase-only resume 自动 rebind policy；语义 edit review-required；complete/clear close；历史 Assessment 按架构保留。grant/预算行为留到 P6/P7 验收。
- 未确认或空 successCriteria 的 attach 为 0 次状态写入并返回 typed error；P5 可直接消费已确认 criteria。
- 连续迁移两次结果相同，legacy Store 字节不变；损坏/未知 v2 Store 不被清空覆盖。
- Supervisor 缺席时 upstream seam 对 stock transcript/调度行为无可观察差异。
