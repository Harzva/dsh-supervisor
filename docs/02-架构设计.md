# 会话矩阵 Supervisor 系统架构设计

## 分层

```text
配置/持久层
  mentors 配置 + supervisor-state.v1.json
        ↓
领域服务层
  SupervisorRegistry → AssignmentService → ModelRouter → HealthTracker → HandoffService
        ↓
通道层
  /dsh-supervisor/* JSON API + session/event
        ↓
界面层
  稳定矩阵 → SupervisorLane/SVG → 角色模型配置/详情/Handoff 抽屉
```

Host 是 Supervisor 身份、分配、角色模型覆盖、健康度、Handoff 和会话创建的权威；Client 只负责展示与发出明确操作。会话本身仍由 DSH 原生 Session/Agent 服务拥有。

## 最终文件树

```text
lib/
  index.js                    插件装配、旧监管引擎兼容层
  client.js                   输入区 Supervisor 浮窗
  mentor-registry.js          Supervisor 配置、角色、模型路由校验、颜色和分配算法
  supervisor-store.js         原子持久化、版本校验和有界审计
  handoff-service.js          Handoff 状态机与幂等事务
test/
  mentor-registry.test.js
  supervisor-store.test.js
  handoff-service.test.js
docs/
  01-需求分析.md
  02-架构设计.md
  03-开发计划.md
  05-验收报告.md
```

矩阵客户端当前位于 `zhitro-brandos-session-board/lib/client.js`。后续可迁移到 `src/client/*` 并生成单一 bundle；在构建迁移完成前，继续保持当前 Loader 合约，避免一次改动同时引入新构建链风险。

## 关键契约

`MentorDefinition`：`id/name/role/responsibilities/route/color/avatar/permissions`。

`MentorAssignment`：一个主导师、最多两个协作导师、来源、原因、时间和版本。

`SupervisorModels`：`{ [supervisorId]: "provider/model" }`。作用域为单个会话；空值表示继承该 Supervisor 的配置路由或会话默认路由。旧 `mentorModel` 保留兼容，但新界面只写角色映射。

`HandoffRecord`：固定目标会话 ID，状态从 `recommended` 进入 `requesting_draft/drafting/ready/creating_successor/delivering/completed`；失败进入 `failed_retryable`。

## 依赖方向

- `index.js` 可依赖所有领域模块。
- `handoff-service` 依赖 store、registry 和宿主会话供应接口。
- registry/store 不依赖 Cordis、React 或 HTTP。
- Client 不 import Host 对象，只消费公开 JSON DTO。

## ADR

| 决策 | 原因 |
| --- | --- |
| 卡片固定 252px | 杜绝异步内容改变 Grid 行高 |
| 快照排序 | 状态轮询不应移动用户的空间记忆 |
| 颜色绑定 mentorId | 跨卡片保持身份一致 |
| 一主责、最多两协作 | 信息充分且不挤压卡片 |
| Host 持久化业务状态 | 浏览器刷新不能丢失责任与交接 |
| 模型覆盖按 session × supervisorId 存储 | 一个角色负责多卡时可分别路由，切换主责后自动命中对应模型 |
| 点击角色卡只打开配置 | 避免查看模型时误切主责；“设为主责”保持独立显式操作 |
| 固定 targetSessionId | 让创建重试天然幂等 |
| 源会话只标记不删除 | 保留可追溯性和恢复路径 |
