# P0 rollback readiness

The pinned `0.2.4` rollback artifact remains byte-identical to its pre-P0 digest and is excluded from all temporary pack destinations. Upload review found a historical runtime session identifier inside its documentation, so the original artifact is now an explicitly Git-ignored local-private rollback input. Git records only its digest and sanitized provenance; the binary is never committed or uploaded. P0 did not execute a legacy Store edit, Profile install, Loader mutation, explicit restart or rollback action.

Artifact rollback readiness passes on the originating machine because the original private artifact is present and verified. Production Profile rollback readiness is blocked: the package manifest, compositions, bootstrap patch and Loader row still match their recorded digests, but the Profile lockfile changed during the closure window. Causality is unproven, no recovery was attempted, and the old lockfile bytes are not reconstructed from a digest. A clean clone verifies the recorded artifact digest and deliberately reports the private artifact as absent. Physical reinstall or Loader-row changes were intentionally not exercised because P0 does not authorize production Profile mutation.

The post-artifact Client fix is deliberately preserved in canonical `src/client.js`; restoring the pinned tarball would also restore the older Client. Any future runtime rollback must therefore be an explicit operator action with that known UI delta, never an automatic P0 cleanup.
